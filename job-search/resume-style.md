# CC 履歷製作規則（每次改履歷都要照做）

CC 2026-10-15 指示：以後做履歷都要「不要太 AI」，並依照被翻牌機率高的最新樣板製作。
用 resume-tailor skill 時，這份規則和 skill 一起適用（skill 的「不編造、只重排／改寫」原則不變）。

## 1. 不要太 AI（招聘人員常見的 AI 履歷特徵，避開）
- 不用空洞流行詞：results-driven、passionate、fast-paced environment、end-to-end、leverage、
  spearhead、drive/drove cross-functional initiatives、systemic、streamline、synergy、
  commercial decision-making、dynamic、proven track record
- 句子要短、句型要錯開：不要每點都是「動詞 + ..., -ing 子句」
- 保留具體細節：數字（5–10 件／週、縮短 50% 以上）、市場（HK/TW）、案件類型（wrong-amount）、系統名稱
- 用平實的動詞：resolve、reconcile、check、maintain、find、work with、wrote
- 摘要 2–3 句，不寫形容自己個性的話
- 不寫不具體的空泛句（例：「Built foundational knowledge...」這種刪掉）
- 寫完自己再讀一遍：像真人跟主管報告做了什麼，而不是像範本

## 2. 被翻牌機率高的版型（2026 主流建議）
- 由新到舊（reverse-chronological），單欄
- 標準標題：SUMMARY／EXPERIENCE／EDUCATION／SKILLS（ATS 讀得到）
- 不用表格、文字框、圖示、照片、多欄
- 一頁為原則；舊的經歷精簡成 1–2 點
- SKILLS 分行：Excel／Systems／Other／Languages
- Languages 要寫：English (daily working language with HK team), Mandarin (native)
  （CC 跟香港團隊主要用英文溝通，偶爾中文）
- 字型與配色沿用 base_resume.docx（Calibri、深藍標題、分隔線），日期靠右對齊頁緣

## 3. 每次製作前
- 先上網快速查一次當下的履歷趨勢／recruiter 建議，有新的共識就更新這份檔案
- 輸出：一頁 PDF，檔名 Cellia_Chou_Resume_<公司>.pdf
- 履歷檔有個人聯絡資料，不上傳 GitHub（job-search/resumes/ 已在 .gitignore）
